# decisions

## Entries

* [No public sign-up; users created via console; passkeys](/decisions/01M7A3TWQGX6E3JH8E286BHKZC.md) - There is no sign-up page or endpoint. Users are created only with a console command. Sign-in is email+password plus passkey (WebAuthn) via Better Auth. Reason: self-hosted, single-person app exposed publicly on Coolify.
* [In-process refresh timer, manually triggerable](/decisions/01M7A3TWS2SA5QF150AFJ2P4Y8.md) - Feeds refresh from an in-process interval timer in the server, plus manual refresh of one feed or all. No external cron. Reason: single Coolify container, simplest option.
* [No offline support or extra integrations in v1](/decisions/01M7A3TWTQQKX8ZNA17MF254CV.md) - v1 is an online-only PWA (installable, app shell cached, data fetched live). No offline article caching, Fever/Google Reader API, push notifications or in-app social sharing. Only a share-link button for article URLs. Reason: keep it simple; offline can be v2.
* [Three-pane layout, Readability extraction, FTS5 search](/decisions/01M7A3TWWCRKT1SNF96RKW8212.md) - Desktop is three panes (sidebar/list/reader), mobile stacked. Full-text extraction uses Readability. Search uses SQLite FTS5. UI uses shadcn-svelte components only.
* [Use better-sqlite3 with Drizzle, not node:sqlite](/decisions/01M7A44AKKCXM9N7TX3Q9EXPDC.md) - Installed drizzle-orm 0.45.2 has no node-sqlite driver (only in 1.0 betas), so the DB uses drizzle-orm/better-sqlite3. Stable, FTS5 built in. Reason: scaffold imported a non-existent driver and caused 500s.
* [Committed drizzle migrations applied at boot; per-worktree SQLite](/decisions/01M7A5RGRVRM8Z1E8NSY3N42KB.md) - Schema changes use drizzle-kit generate with migrations committed under drizzle/ and applied at server start (init() in hooks), never db:push. Parallel worktrees each use their own relative DATABASE_URL (local.db) and dev port so SQLite files never collide. The /feeds management page belongs to the feed-subscribe issue; the sidebar only links to it.
* [Deploy as single Node container, ORIGIN env only](/decisions/01M7A62RBVV6P1CRSAPD8FDFDK.md) - Image is node:24-bookworm-slim multi-stage, non-root, SQLite on /data volume, single replica, CMD node build. Behind Coolify's proxy ORIGIN set to the public https URL is sufficient (no PROTOCOL_HEADER/HOST_HEADER). Retention is a per-user DB setting, not an env var. Image build is still unverified (Docker daemon was down).
* [safeFetch decodes compression with decompressed size cap; HTML sanitized at ingest and render](/decisions/01M7A79HP18TJZR0VER8DKN1AJ.md) - safeFetch sends Accept-Encoding gzip/deflate/br and decodes via node:zlib with the size cap enforced on decompressed bytes (rejecting compressed responses breaks real feeds that ignore identity). Content is sanitized when parsed/ingested (relative URLs resolved against item link, rel noopener) and again at render time in the reader. Fetches are pinned to the validated IP (SSRF). Reason: found in review of the feed subscribe issue.
* [OPML import inserts feeds without fetching; UI lives on /feeds until settings exists](/decisions/01M7A79HQRA3YKPAJ9HJHTW21Y.md) - OPML import creates feeds with next_fetch_at=now and lets the scheduler fetch them, so large imports are instant. The import/export panel is mounted on the /feeds page; the later settings issue may move it. Reason: avoid blocking requests and avoid parallel-issue conflicts on a not-yet-built settings page.
* [Scheduler: safe last_error, manual refresh cooldown with feedback, 30 min default](/decisions/01M7A8PZJH36WHT1PVAR4P42BN.md) - last_error stores messages only from FeedFetchError/FeedParseError (truncated), anything else becomes a generic message and is logged server-side. Manual refresh has a 30s per-feed cooldown that reports 'skipped' instead of pretending success. Default refresh interval is a shared DEFAULT_REFRESH_MINUTES=30 used by both subscribe and OPML queueing. Reason: review findings on the refresh scheduler issue.
* [Seed script may hold the dev credentials but must refuse non-local runs](/decisions/01M7A8PZMHVPCAQG1QA2P91MEJ.md) - The user allowed committing the throwaway dev account (same as the justfile create-user recipe) in the seed script. It must exit before touching the DB when NODE_ENV is production or ORIGIN is not localhost, because the public Coolify deployment has no sign-up and a known-password account there would be a backdoor. Reason: user stated it is not personal data; guard makes it safe to publish.
* [Reader state mutations use a JSON endpoint with optimistic client state](/decisions/01M7A9QAK9D9KD6RFBVT3SZ7YB.md) - Read/star/mark-read mutations go through POST /api/state (session required, same-origin check, JSON content type, validation, 404 on unowned ids) with optimistic overrides in reader-state.svelte.ts, rollback plus toast on failure, and refetch on focus/visibility plus a 60s poll. Reason: simplest way to get instant optimistic updates and cross-device sync; reviewed in a real browser.
* [Desktop layout uses fixed pane widths, not resizable panes](/decisions/01M7A9QANAZ3VRMBVM6EDHR7MK.md) - The implementer replaced the draggable resizable panes with CSS fixed widths (sidebar w-72, fixed list column) and CSS-only responsive switching, which removed the SSR layout flash. A browser review judged it acceptable for the simple clean design; it is cramped at about 1024px, tracked in the list follow-up issue. Restore resizing later only if wanted. Refines the three-pane decision.
* [Views host the list in a layout; lists are capped with Load more; sync invalidates narrow keys](/decisions/01M7AB1NE912NXF9NTE7PJD6BJ.md) - Each view (all, unread, starred, feed, folder) has a +layout that hosts the list so it persists when an item opens (item is a nested page); lists load the 100 newest with cursor-based Load more via GET /api/articles and the open item is always merged in; sync (focus, visibility, 60s poll) invalidates app:list, app:item and app:feeds instead of invalidateAll and refetches extra pages in chunks of 100. /api/state caps bodies at 4096 bytes. New views such as search should reuse this layout pattern. Reason: scroll position and cost at scale, verified in a real browser.
* [Full-text extraction must not parse HTML on the main thread unbounded](/decisions/01M7AB1NFZ6JCXQ46D0PECVX0P.md) - Review measured linkedom plus Readability freezing the server for over a minute on a 49 KB page of deeply nested divs; the fetch timeout cannot interrupt synchronous parsing. Extraction therefore must parse in a terminable worker thread (or equivalent) with a hard timeout, plus cheap pre-rejection by tag count and nesting depth and a lower byte cap, and must work in vite dev, vitest, node build and the Docker runtime image.
* [Extraction parses in an eval worker thread, not a bundled worker file](/decisions/01M7ABPYQ9MZ9NSA2C1VYAHVEV.md) - dom-worker.ts creates short-lived worker threads with {eval:true} from inline CommonJS that loads linkedom and @mozilla/readability via createRequire(import.meta.url), because bundled worker file URLs are unreliable across vite dev, vitest, node build and the Docker runtime (prod node_modules, no src/). Limits: 5s terminate, 256 MB old-gen, max 2 workers with a queue, pre-scan (50k tags, depth 150), 1 MiB page cap. Verified in node build from another cwd with no src/.
* [Seed uses real feeds pulled by the app, not fake data](/decisions/01M7ACNV4AK2AWEKXPFSPP431S.md) - User decision: a seed with fabricated feeds and items veils real problems. The seed creates the dev user and folders and queues real popular feeds (verified live 2026-11-13, covering RSS, Atom, RSS 1.0, JSON Feed, gzip/br, redirects, a wrong content type, large feeds and one dead URL); the running app's scheduler pulls them. The script itself stays network-free and keeps the production guard. Supersedes the seed issue's fake-fixture design; the guard decision still applies.
* [Search index is trigger-synced FTS5 using an app-defined SQL function; only app connections may write items](/decisions/01M7ACP9XWR54E4KDYJT01M463.md) - items_fts is kept in sync by triggers that call item_search_text/item_clean_title, SQL functions registered in connectDatabase(). Every writer must use connectDatabase (app boot, seed, create-user, scheduler). drizzle-kit migrate, push and studio cannot write items (no such function) so db:migrate and db:push refuse with a message; app-boot migration is the supported path, db:generate stays fine. search-text.ts lives in src/lib/server/db/ so the Docker runtime image (which copies that folder) can run user:create. Reason: automatic re-index of any items UPDATE including extraction's full_content.
* [Retention prunes only read, unstarred items and leaves tombstones](/decisions/01M7ACP9ZPJG9SHGB5BNZS79D6.md) - Daily job (2 min after start, then every 24 h) deletes items the owner has read, not starred, older than user_settings.retention_days (default 30, <=0 keeps all), in transactions of 200 with yields. A pruned_items(feed_id, guid) tombstone written in the same transaction makes ingestItemIds treat them as already seen so pruned items still present in their feed never return as unread or get re-extracted. Items without an item_state row (never opened) are unread and are never deleted. Lowering retention later cannot restore pruned items; tombstones are tiny and cascade with their feed.
* [Feed titles are decoded once as plain text; extraction page cap is 2 MiB; transient network errors are safe](/decisions/01M7AP1FT4RHRZMG8DHTG4MDBG.md) - plain() in parse.ts decodes entities exactly once and strips tags with no spaces added at tag boundaries (CO<sub>2</sub> stays CO2), strips control characters and falls back to 'Untitled' for items. MAX_ARTICLE_BYTES is 2 MiB: Wired pages are up to 1.56 MB and a larger cap risked a worker heap OOM crash on hostile pages (3 MiB was measured fine on adversarial inputs but 2 MiB is tighter). Transient network failures (ENOTFOUND, ECONNREFUSED, ECONNRESET, ETIMEDOUT, EAI_AGAIN...) store the safe last_error 'Could not reach the server.' and log one line without a stack. Found by pulling real feeds.
* [Per-feed settings live in Settings; user-supplied names go through cleanSingleLine](/decisions/01M7AP1FW00FGWJ0QR3BSXJVQF.md) - Settings page (Reader, Feeds, Retention, Security tabs) owns per-feed title, refresh interval presets and the full-text toggle; /feeds keeps subscribe, remove, folders, refresh and OPML. Reader prefs (font 14-24, width 480-1000) are validated integers applied as CSS variables in the server-rendered layout. Custom feed titles and folder names go through cleanSingleLine (src/lib/server/clean-text.ts) which strips control and bidi override characters and collapses whitespace. Passkey add/rename/delete use Better Auth's passkey client; passkey sign-in was verified end to end with a WebAuthn virtual authenticator.
* [Prefer opencode with OpenAI GPT for implementation and review when usage allows](/decisions/01M7AP1K9Q8FBVZTZSW3SQDJTJ.md) - User instruction: hand off as much work as possible to opencode agents while OpenAI usage is plentiful. Implementation and review both run through opencode-handoff in separate sessions (reviewer different from implementer), in worktrees with .env and the Playwright toolkit pre-staged inside (opencode denies external directories). Claude sonnet subagents are the fallback when OpenAI usage is exhausted. Check ai-usage before launching.
* [Mobile gestures: swipe left = next article; row swipe right = read, left = star; hamburger stays](/decisions/01M7AQD6XMSNKYP13DSQJDB7T6.md) - User decisions (2026-11-13): in the reader, swiping left goes to the next article (standard paging, swipe right = previous); keep the hamburger drawer for navigation for now (a bottom tab bar is deferred, revisit later). Delegated to the orchestrator and accepted: list rows swipe right toggles read and left toggles star (Reeder convention), configurable in Settings later; long-press or an overflow button opens a row menu; every gesture has a visible alternative; mark-all-read asks for confirmation when it affects many items and always offers an Undo toast; mark-as-read-on-scroll is NOT built now (possible opt-in setting later, default off); the reader gets a bottom action bar (star, read, share, original, prev/next).
* [Edge-swipe navigation cannot be disabled; design around it](/decisions/01M7AQD6ZE14JEYCW5V5YWFE3Q.md) - Research: iOS has no official way to disable the standalone PWA swipe-back gesture (CSS overscroll-behavior-x:none stops history redirect but not the animation; a touchstart preventDefault edge guard is partial and fails while the page is scrolling); on Android the system back gesture is OS-level and cannot be disabled by a web app, while Chrome's own in-page history swipe is controlled by overscroll-behavior-x. Decision: do not try to disable them. Gestures of our own must ignore touches that start within about 24-28 px of either screen edge; set overscroll-behavior (x and y) so Chrome history swipes and pull-to-refresh reloads are off inside the app; make Back (system gesture, edge swipe or button) always return from the article to the list with scroll preserved (already history-aware); optionally try a touchstart edge guard on iOS but verify on a real device and do not depend on it.
* [Sidebar collapse state lives in an SSR-readable cookie](/decisions/01M7ARSVHSX8PK6WZCFPE607QM.md) - Collapsed folder ids are stored in a cookie (sidebar collapsed set, max 80 ids, about 3.8 KB, pruned to the current user's folders, SameSite=Lax, one year) read in the (app) layout load so the first server render is already correct. localStorage persistence was rejected because it caused a visible expanded-then-collapsed flash (layout shift 0.074) after hydration; the cookie version measured about 0.00015 under 4x CPU and delayed JS. Folder ids are per-user UUIDs so a shared browser cannot leak state; the active view's folder always stays expanded.
* [Never delete the developer's local.db while their dev server runs](/decisions/01M7ARSVKQ07BBKRC4WCWE3HD7.md) - Deleting local.db under a running dev server leaves it holding handles to the deleted file: its in-process scheduler (a globalThis singleton) and the manual Refresh write into a database nobody reads, so the user sees no articles (happened 2026-11-13). Agents verify against a throwaway DATABASE_URL (for example verify.db inside the project, deleted afterwards) or in their own worktree, never the main checkout's local.db; if a schema or seed change needs a reset, tell the developer to restart the dev server. The dev server also keeps the scheduler across hot reloads, so changes to fetch/parse/extract code need a restart.
* [Reader article enhancements only move nodes; image viewer rules](/decisions/01M7ASDXKT5BKG69YXCEYJANRS.md) - Post-render enhancements (src/lib/reader-enhancements.ts, article-image-viewer.svelte) never use innerHTML or insertAdjacentHTML with article content: they wrap tables and pre blocks in their own horizontal scroll regions, set attributes, and add links via textContent. External http(s) links open with target=_blank and rel noopener noreferrer; other schemes stay under the sanitizer's policy. Images open an accessible viewer on a plain tap (pinch and double-tap zoom, swipe-down or button close); images under about 48 px or with 0/1 size attributes (tracking pixels, emoji) are ignored; an image inside a link opens the viewer on a plain tap while ctrl/meta/shift/alt/non-primary clicks pass through to the link. The action toolbar collapses on scroll down and always returns at the top, at the end of the article and for non-scrolling articles. The article scroller [data-reader-scroller] and horizontally scrollable regions [data-reader-horizontal-scroll] are the hooks for the later swipe-between-articles gesture, which must ignore touches starting in those regions or in the viewer.
* [Cap parallel opencode sessions; use Claude for adversarial security probing](/decisions/01M7ASDXNQJ84KD53HT1ZZFF19.md) - Six parallel opencode GPT sessions exhausted the OpenAI 5-hour window (99-100%) in a few hours and killed a review mid-run; an opencode review of the extraction DoS fix was also blocked by OpenAI's cyber_policy filter while probing adversarial HTML. Rule: run at most three opencode sessions at a time, check ai-usage before each launch, and use Claude sonnet reviewers for adversarial or security-probing reviews and as the fallback when OpenAI usage is exhausted; opencode GPT stays the default for implementation and ordinary reviews.
* [Tiered agents: haiku for obvious edits with batch review; sonnet or GPT with per-issue review for risky work](/decisions/01M7ATMGE76193784F7YG64535.md) - User-approved (2026-11-13): use haiku (or the local gemma4 via opencode for tiny mechanical edits) for obvious, local, already-specified edits (renames, copy and label changes, class tweaks, dead-code deletion, tests following an existing pattern, README text) and review them once per batch of about five tasks, each task in its own commit with its own check/test/build/lint gates and the reviewer pointed at the task commit list. Anything touching fetch/parse/sanitizer, auth or passkeys, the database or migrations, concurrency, gestures, global CSS or layout, or user-controlled rendering stays on sonnet or opencode GPT with an independent per-issue review (reviews caught a real defect in almost every non-trivial issue so far: worker DoS, Docker blocker, spoofable highlights, quadratic pre-scan, title regression, layout overflow). Gemma output is always diff-checked (it dropped a selector mid-edit once) and took 6.8 minutes for a five-line CSS edit.
* [Use agent-browser for all browser testing](/decisions/01M7ATVQQAGN7VTX6TT9NENPRD.md) - User instruction (2026-11-13): use the agent-browser CLI (installed globally with pnpm, binary in ~/Library/pnpm/bin) instead of Playwright scripts for browser testing because it is more token efficient: own session per agent (agent-browser session id --scope worktree), snapshot -i with @eN refs rather than screenshots, screenshot --if-changed only for visual judgement, set device/viewport/media for emulation. Raw touch swipes (Input.dispatchTouchEvent) and safe-area insets (Emulation.setSafeAreaInsetsOverride) are not agent-browser commands: use a small CDP script against 'agent-browser get cdp-url' (Node has a global WebSocket) or synthetic pointer events via eval. The Playwright toolkit staged in worktrees is no longer needed; the repo-level mobile test harness issue may still add Playwright as a dev dependency for committed tests.
* [Mobile foundations: phone-only 44 px targets, safe-area aliases, scoped overscroll, shared gesture helper](/decisions/01M7AVNBNQ3TAXJ696941PWWZB.md) - Phone rules live in layout.css under max-width 1023px: interactive elements at least 44 px with at least 8 px spacing (switch/checkbox rows widened with ::after), 16 px inputs, tap highlight, links inside running text (p, description slots, article prose) are exempt so paragraphs are not stretched. Safe areas: viewport-fit=cover with --sat/--sar/--sab/--sal aliases used by the header, drawer, main content and sonner offsets. overscroll-behavior none only for (pointer: coarse), (display-mode: standalone) so desktop trackpad swipe-back keeps working. iOS status bar style stays default (black-translucent makes white status text unreadable on the white header). src/lib/gestures.ts is the shared pure helper for the swipe issues: GESTURE_THRESHOLDS {edgeMargin 28, deadZone 10, axisRatio 1.25, commitDistance 80, commitVelocity 0.5, minimumFlickDistance 24}, isEdgeStart, lockAxis, gestureDirection, shouldCommitGesture, articleStep (left = +1 next, right = -1 previous); non-finite inputs fall back to defaults. Verified: desktop pixel-identical to main at 1280 and 1920, 0 touch targets under 44 px on audited screens, emulated safe-area insets. Open for later issues: user-select none on list rows vs the long-press menu, velocity estimator and per-side thresholds, real-phone checks (see the issue log).
* [Article navigation replaces history once an article is open](/decisions/01M7B3WSRD72MH59799HWC8C3Z.md) - Swipe, prev/next buttons and j/k all use goto with replaceState once an article is open, so one Back returns to the list. If no article is open yet, j/k still pushes. Reason: the issue requires Back to return to the list in one step, and keeping j/k consistent with swipe avoids two behaviours. Also: prep records are not in agent worktrees, so subagents must run prep with --root pointing at the main checkout.
* [Folder refresh runs refreshFeed per feed](/decisions/01M7B7BBWEBFGDDBDT2MHVZ8T2.md) - There is no folder refresh action, so in a folder view refresh() (pull, Refresh button and the r shortcut) calls refreshFeed once per feed in that folder and shows the worst outcome (error, warning, success, info). Previously r on a folder refreshed everything. Reason: the issue says a folder view refreshes the feeds in the folder and the pull must follow the same rules as r. Toast kind is derived by refreshMessageKind in src/lib/shortcuts.ts.
* [Mobile e2e uses Playwright with a seeded private DB](/decisions/01M7B85K9JDQFXAVS1CN6R0MZZ.md) - Mobile tests run with @playwright/test (pnpm test:mobile) on iPhone 14 and Pixel 7 chromium projects, using CDP touch events, against a production build and a private seeded DB at .e2e/mobile.db (gitignored, never network). Reason: the issue needs automated touch tests with a device checklist for what emulation cannot cover; a private DB keeps the developer's local.db safe. agent-browser stays the tool for ad hoc agent checks.
* [Identifiable User-Agent and per-host fetch cap of 2](/decisions/01M7B8G0T6Y2J1J8G655GSMYR6.md) - The fetcher sends 'RSSReader/1.0 (+<url>)' with the project URL as default and RSS_READER_CONTACT as an override (URL or mailto), documented in README and .env.example. The scheduler caps fetches at 2 per host inside the global limit of 4. Embeds removed by the sanitizer leave an 'Embedded content not shown. Open original' hint, with the link omitted for unsafe URLs. Reason: polite, identifiable crawling and no bursts against one host.
* [View transitions animate only the outgoing snapshot; skipped for swipes](/decisions/01M7B9FAP0V2AK0XGD8EGNT4R5.md) - List<->article navigation uses document.startViewTransition (feature-detected, skipped under reduced motion). Only the outgoing snapshot animates so the live article receives gestures immediately, and article-to-article swipe navigation never starts a view transition (it keeps its own slide). Rows keep touch-pan-y (no pinch-zoom). List links preload on tap. Reason: a full cross-fade blocked touches for ~100-150 ms after navigation and broke the mobile e2e swipe test. Cost: first full article paint is ~35 ms slower than before on 4x CPU / Fast 3G, accepted for the earlier skeleton.
* [First user in the container is created with node --import tsx, not pnpm](/decisions/01M7B9SKA8HPBPWXWQ3EFEC2E1.md) - The documented first-user command inside the production image is docker exec <container> node --import tsx scripts/create-user.ts --email ... --name ... --password ... (same for docker compose exec). Reason: the image runs as non-root node and pnpm via corepack cannot download or write its cache at runtime (EACCES, needs network). tsx is a production dependency and the script is already in the image. Local dev still uses pnpm user:create.
* [Coolify: Dockerfile build pack, Coolify-run healthcheck with curl in image](/decisions/01M7CTVHMFG1JDMYVENWD88A9R.md) - Deploy on Coolify with the Dockerfile build pack (not compose or Railpack); Coolify's rolling-update healthcheck gates cutover, so the runtime image installs curl.
