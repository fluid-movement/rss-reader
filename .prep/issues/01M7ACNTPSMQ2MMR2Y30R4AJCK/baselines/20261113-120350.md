The dev seed must not fake data. Replace the generated fixtures (fake feeds, fake items, fake read/starred state, example.com URLs) with REAL, popular feeds that the application pulls itself, so the seed exercises the real pipeline (safeFetch, compression, parsing of RSS/Atom/RSS 1.0/JSON Feed, sanitization, scheduler, extraction, search) and surfaces real problems instead of hiding them.

Behavior: `pnpm db:seed` (and `just seed`) recreates the dev user (same credentials as today, see scripts/seed-data.ts), creates topic folders, and queues the real feeds below for the user via the existing OPML-style `queueFeed` service (no network access inside the script; feeds are due immediately, `next_fetch_at` = now). The running app's in-process scheduler then pulls them (the dev server must be running; document that, and optionally add a `--refresh` flag that runs one refresh pass through the scheduler's `refreshAll` so a seed without a running server still fills). No fake items and no pre-made read/starred state. Keep the safety guard (refuses NODE_ENV=production, non-localhost ORIGIN, DATABASE_URL outside the project), idempotency (delete and recreate the dev user), tests and README. Some feeds should have `extract_full_text` on (excerpt-only feeds) and one or two a custom refresh interval, so those paths run against real pages too.
