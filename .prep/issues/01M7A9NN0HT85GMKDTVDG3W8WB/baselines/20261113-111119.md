Follow-ups from the review of the read/star state issue.

1. Opening an article remounts the reader workspace because each list and item route has its own page component, so the list scroll position resets to the top when opening an item and when returning on mobile. Host the workspace in a shared layout (for example one view-level +layout.svelte) so the list persists, or save and restore scroll position; verify on desktop and phone.
2. getReaderData loads every item of a view with no limit, and every mutation, focus refetch and the 60s poll reloads the whole list. Add a sensible cap or pagination/infinite loading (newest first), keep the open item always included, and invalidate narrowly where possible (depends keys) so polls do not refetch everything.
3. /api/state has no request body size cap (a 5 MB body is parsed before the 404): add a small content-length cap and limit olderThanDays range.
4. Starred has a hard-coded count of 0 in the sidebar data: either show a starred total or remove the dead field.
5. Cosmetics: sidebar bottom clipping at 800 px height (Manage feeds row hidden behind the footer), bold folder badges versus muted feed badges, reader narrow at 1024 px width (consider a narrower or collapsible sidebar below about 1150 px).

Keep the optimistic UI, rollback, focus/visibility/poll sync behavior intact and re-verify it in a real browser.
